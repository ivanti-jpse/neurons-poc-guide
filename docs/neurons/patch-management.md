# パッチ管理の初期設定〜検証

Ivanti Neurons for Patch Management(コンソール上の表記: [パッチ管理])は、クラウドネイティブなパッチ適用ソリューションです。本ページでは、パッチ設定(スケジュール)の作成からエージェント ポリシーへの反映、脆弱性・Patch Intelligence の確認、手動/スケジュールパッチの実行結果確認、レポート作成までの一連の POC フローを解説します。

## 全体ワークフロー

パッチ管理のクラウド ワークフローは、次の流れで構成されます。

``` mermaid
graph LR
  A["1. パッチ設定<br>の作成"] --> B["2. エージェント ポリシーで<br>パッチ機能を有効化"] --> C["3. デバイスへの<br>反映確認"] --> D["4. 脆弱性/Patch<br>Intelligence 確認"] --> E["5. パッチ配布<br>(スケジュール/手動)"] --> F["6. 配布履歴・<br>レポートで結果確認"]
```

以降、この流れに沿って POC 環境での操作手順を解説します。

## 手順本体

### 1. パッチ設定(定期メンテナンス)の作成

**[パッチ管理] > [パッチ設定]** の **[構成]** タブで、**[構成を作成]** をクリックし、新しいパッチ構成を作成します。

1. **構成名** を入力します(例: `POCガイド_定期メンテナンス`)。
2. **[構成動作]** タブの **Windows 配布の動作** で、**[定期メンテナンス]** がオンになっていることを確認します。
3. **[このタスクを構成]** をクリックし、スケジュールを設定します。
    - **パッチの配布**: 翌日の配布結果を確認する POC の場合は **[日単位]** を選択し、**[配布]** に当日中の任意の時刻(例: `23:00`)を指定します。次回のチェックイン時に配布が開始され、翌日には配布履歴で結果を確認できます。
    - **[配布前にコンテンツをステージング]** は既定のままで問題ありません。
4. 画面右上の **[保存してアクティブにする]** をクリックします。

保存直後は **可用性** が **[保留中]** と表示されます。これは手順2でエージェント ポリシーに関連付けるまでの状態で、関連付け後に **[アクティブ]** に変わります。

### 2. エージェント ポリシーでパッチ機能を有効化

**[エージェント] > [エージェント ポリシー]** で、対象デバイスに割り当てられているポリシーを開き、**[編集]** をクリックします。

1. **[機能]** タブの **[パッチ管理]** カードが有効(チェック済み)になっていることを確認します。未設定の場合はチェックを入れます。
2. **[パッチ管理]** カード内の **構成** ドロップダウンから、手順1で作成した構成(例: `POCガイド_定期メンテナンス`)を選択します。
3. 画面右上の **[保存]** をクリックします。

保存すると **バージョン** が1つ繰り上がります。エージェント設定変更は、次回対象デバイスが Ivanti Neurons にチェックインしたタイミングで反映されます。

!!! tip "検証に使うポリシーの選び方"
    POC では、実際にエージェント エンドポイントが割り当てられているポリシー(**[エージェント ポリシー]** 一覧の **エージェント エンドポイント** 列が1台以上のもの)を選ぶと、手順3以降の反映確認・配布結果確認まで一気通貫で実演できます。0台のポリシーを編集しても、反映先のデバイスがないため確認できません。

### 3. エージェント管理ページでのポリシー反映確認

**[エージェント] > [エージェント ポリシー]** で対象ポリシーを開き、**[エージェント エンドポイント]** タブを確認します。

- 対象デバイスが一覧に表示され、**ステータス** が **[アクティブ]** であることを確認します。
- **正常性** 列のインジケータ(緑=良い、黄=標準、赤=悪い、灰=不明)で、デバイスの現在の状態を確認できます。

デバイスがまだ新しいポリシーをチェックインしていない場合、一覧への反映や正常性の更新に数分〜次回チェックイン分のタイムラグが生じることがあります。

### 4. パッチ管理 > エンドポイントの脆弱性でリスクスコアを確認

**[パッチ管理] > [エンドポイントの脆弱性]** に移動します。

- 画面上部のチャート(**デバイスの正常性**、**前回のスキャン**、**リスク別デバイス**)で、環境全体の傾向を確認します。
- 下部のデバイス一覧の **リスク スコア** 列で、各デバイスの脆弱性リスクを確認します。スコアは0〜100の範囲で、100 に近いほどリスクが高くなります。
    - 赤 = 悪い(70 以上)
    - 黄 = 標準(40〜69)
    - 緑 = 良い(40 未満)
- **未適用のパッチ** 列の数字をクリックすると、そのデバイスで未適用のパッチの詳細を確認できます。

### 5. Patch Intelligence で個々のパッチの信頼性・VRR を確認

**[パッチ管理] > [Patch Intelligence]** に移動し、**[アドバイザリ]** タブで **[環境に影響]** トグルをオンにすると、自環境に関連するパッチのみに絞り込めます。

一覧からパッチ名をクリックすると、パッチ詳細ページで以下の情報を確認できます。

- **ベンダ重要度**(例: セキュリティ:重大)
- **VRR**(脆弱性リスク評価。0〜10のスコアで、数値が大きいほどリスクが高い)
- **報告された問題**、**影響を受ける製品** 数
- **[CVE]** タブでは、パッチに含まれる CVE ごとの **VRR グループ**・**VRR スコア**・**CVSS スコア**・エクスプロイトの有無を確認できます。

### 6. スケジュールパッチの実行結果確認(翌日)

!!! warning "翌日の待機が必要な手順"
    本手順は、手順1で設定した定期メンテナンスのスケジュール配布が実際に実行された**翌日**に確認します。実施日にその場で結果を確認することはできないため、以下は確認方法と確認手順のみを記載します。

翌日以降、以下の手順で結果を確認してください。

1. **[パッチ管理] > [配布履歴]** に移動します。
2. 一覧の **デバイス名** 列で対象デバイスを、**配布構成** 列で手順1のパッチ構成名を絞り込みます。
3. **ステータス** 列が **[成功]** であることを確認します。**[保留中の再起動]** や **[再試行回数を使い切りました]** 等が表示された場合は、本ページ末尾の「トラブルシューティングの入口」を参照してください。
4. **[パッチ管理] > [エンドポイントの脆弱性]** で、対象デバイスの **リスク スコア** および **未適用のパッチ** 数が配布前より減少していることを確認します。

### 7. 手動パッチ(デバイスビューからの個別配布)

**[デバイス]** ワークスペースまたは **[パッチ管理] > [エンドポイントの脆弱性]** から対象デバイス名をクリックし、デバイス詳細ページの **[パッチ]** タブを開きます。

1. 一覧から配布したいパッチ(ステータスが未適用のもの)の行のチェックボックスを1つ選択します。
2. **[パッチ アクション]** メニューから **[選択した未適用のパッチを配布する]** を選択します。
3. 画面右上に「デバイスに配布する◯件のパッチを処理しています」という通知が表示され、対象パッチのステータスが **[配布中]** に変わることを確認します。

### 8. 配布履歴で手順6・7の結果を確認

**[パッチ管理] > [配布履歴]** に移動し、一覧の **パッチ名**・**デバイス名** 列で、手順6(スケジュール配布)・手順7(手動配布)それぞれの対象を検索します。

- 手動配布(手順7)は、実行直後は **ステータス** が **[実行中]** で表示され、完了後に **[成功]** または **[失敗]** に変わります。
- チャート **[経時的なパッチ配布]** で、選択した期間内の成功/失敗の推移を確認できます。
- **[失敗と警告の上位10]** チャートで、失敗が発生している場合の主な原因を確認できます。

### 9. レポートの作成

**[パッチ管理] > [レポート]** に移動し、**[新規レポートの作成]** をクリックします。

1. **ステップ1(レポートを選択)**: 用意されたテンプレートから1つ選択します(例: **デバイス (CVE 別) - 概要**)。
2. **ステップ2(レポートの詳細)**: レポート名を入力し、出力形式(PDF / CSV / Excel)とスケジュール(オンデマンドのみ / 繰り返されるスケジュール)を選択します。
3. **ステップ3(フィルタ)**: 対象とする CVE・デバイスの範囲を指定します(POC では「すべての CVE」「すべてのデバイス」で問題ありません)。
4. **ステップ4(レポートを共有)**: 必要に応じて共有先メールアドレスを指定し、**[レポートを送信]** をクリックします。

作成が完了すると、レポート一覧の **ステータス** が **[完了]** に変わり、ダウンロードできるようになります。生成には数分〜データ量に応じた時間がかかります。

## 手順後の確認

### コンソール側

- **[パッチ管理] > [パッチ設定]** の構成一覧で、対象構成の **可用性** が **[アクティブ]**、**関連する** が **[はい]** になっていることを確認します。
- **[パッチ管理] > [配布履歴]** で、対象デバイスの配布結果が **[成功]** であることを確認します。
- **[パッチ管理] > [エンドポイントの脆弱性]** で、対象デバイスの **未適用のパッチ** 数・**リスク スコア** が配布前より改善していることを確認します。

## トラブルシューティングの入口

| 症状 | 最初に確認すること |
| --- | --- |
| パッチ構成が「保留中」のまま「アクティブ」にならない | エージェント ポリシーの [パッチ管理] 機能に、対象の構成が関連付けられているか |
| 配布ステータスが「保留中の再起動」のまま進まない | デバイスの再起動が実行されているか。エージェント ポリシーの [再起動エクスペリエンス] 設定 |
| 配布ステータスが「再試行回数を使い切りました」 | [パッチ結果] 列のエラーコードを確認し、対応後に対象デバイスで [再試行回数のリセット] を実行 |
| デバイスにポリシー変更が反映されない | デバイスが Ivanti Neurons にチェックインしているか(オフライン・通信不可でないか) |
| パッチ配布の権限がなく操作できない | [管理] > [アクセス コントロール] > [ロール] > [権限] > [グローバル アクション] > [パッチの配布] が付与されているか |
| パッチの更新に失敗する | パッチ エンジン(ベンダ/サイドロード)URL の許可設定、ベンダー URL ホワイトリスト CSV の反映漏れ(詳細は [ネットワーク要件](../prerequisites/network-requirements.md) を参照) |
